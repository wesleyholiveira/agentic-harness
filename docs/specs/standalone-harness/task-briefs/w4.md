# Task Brief W4 — Standalone services

**Owner:** `platform-release`

## Objective

Package PostgreSQL/RabbitMQ/Redis/TEI/Context Engine/Rust worker and submodule-safe harness migrations with consumer-scoped Docker runtime identity.

## Owned paths

- `compose.yaml`
- `bin/harness.mjs`
- `scripts/internal/compose-project-identity.mjs`
- `scripts/harness-migrate.mjs`
- `apps/runtime-worker/**`
- `apps/context-engine/Dockerfile`
- `infra/postgres/migrations/**`

## Acceptance

- changes remain project-agnostic;
- distinct canonical consumer roots derive distinct Compose project namespaces and therefore distinct non-external named volumes;
- inherited generic `COMPOSE_PROJECT_NAME` cannot collapse isolation; explicit `AGENT_HARNESS_COMPOSE_PROJECT_NAME` remains bounded and validated;
- `harness:migrate` works from a clean consumer submodule without `.harness/node_modules` by executing the existing migrator in the consumer-scoped `database-migrate` image/network;
- no acceptance criterion is weakened by prose;
- focused validation is executable and recorded;
- handoff records changed paths, validation and residual risks.

## Validation

`npm run harness:test` plus the work-item-specific source/build check from `TEST-PLAN.md`.
